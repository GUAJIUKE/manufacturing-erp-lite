## A. 简历极简版（3–4 bullet，用于项目经历条目）

**Manufacturing ERP Lite — 制造企业采购与库存协同 ERP Demo**

- 设计并实现「采购申请 PR → 主管审批 → 采购订单 PO → 收货入库 → 库存」完整
  业务闭环（前后端分离：Vue 3 + TS + Element Plus / FastAPI + SQLAlchemy + MySQL 8）
- 核心建模：PR/PO/Receipt 三套**单据状态机**、RBAC 权限点 + **对象级权限**
  （审批人=申请部门主管、PO 仅本人可操作）、明细级 PR→PO 来源映射（支持拆单/合单）
- 一致性设计：**乐观锁 + CAS** 防并发超转/超收、库存流水 append-only（DB 触发器
  强制）+ 余额快照对账恒等式、移动加权平均成本、入库过账单事务原子
- 质量：后端 Pytest 229 项 / 覆盖率 91%（门禁 70%）；前端 Vitest 47 项 +
  类型 + 构建；角色隔离 Dashboard（KPI 下钻口径与明细一致）

## B. 招聘平台详细版（约 150–250 字）

面向制造企业采购与库存协同场景，独立设计并实现了轻量 ERP Demo
「Manufacturing ERP Lite」，前后端分离：后端 FastAPI + SQLAlchemy 2 + MySQL 8
（Alembic 迁移、JWT 认证），前端 Vue 3 + TypeScript + Element Plus + Pinia。

业务上打通「采购申请（PR）→ 部门主管审批 → 采购订单（PO）→ 分批收货入库 →
库存」完整闭环，支持部分到货、整单冲销、拆单与合单。工程重点：
① 三套单据状态机收敛于服务层白名单，非法流转一律拒绝；
② 权限三层模型：RBAC 权限点 + 对象级权限（审批必须为申请部门主管，数据可见
范围按角色收敛）+ 单据状态；
③ 一致性：乐观锁与条件更新（CAS）防止并发超转/超收，库存余额行锁 + 统一锁
顺序避免死锁，一次入库 7 类写入单事务原子；
④ 库存账：append-only 流水（MySQL 触发器禁止改删）+ 余额快照，
SUM(流水) == 余额恒等对账，移动加权平均成本；
⑤ 角色隔离 Dashboard：KPI 后端聚合且口径与明细列表一致，支持下钻。
质量：后端 Pytest 229 项通过、分支覆盖率 91%（门禁 70%），前端 Vitest 47 项，
全流程真实 API 可用，五角色演示账号可完整体验。

（投递端口径可微调：技术栈一行、工程重点列 3 点即可。）

## C. 面试 1 分钟介绍（口述稿）

> 建议语速：约 200 字/分钟。讲到第 3 句可顺手打开 Demo。

「我做一个叫 Manufacturing ERP Lite 的项目，定位是**制造企业采购与库存协同
的 ERP Demo**——不是商业级完整 ERP，而是把这类系统最核心的业务闭环和工程
难点做扎实。

业务链是：采购申请 PR → 部门主管审批 → 采购订单 PO → 仓库分批收货 → 库存
记账，支持部分到货、整单冲销、拆单合单。技术栈前端 Vue3 + TS + Element Plus，
后端 FastAPI + SQLAlchemy + MySQL，前后端分离，全流程走真实 API。

这个项目我主要想体现四块设计。第一是**状态机**：PR/PO/Receipt 三套状态收敛在
服务层白名单里，非法流转拒绝，PO 的已收状态由明细数量推导，冲销能自动回退。
第二是**权限**：不是只有 RBAC 权限点，而是权限点 + 对象级权限 + 单据状态三层，
比如有 pr:approve 不代表能批任意部门的单，必须查 department_managers 确认你是
这张 PR 申请部门的主管。
第三是**一致性**：并发超转超收用条件更新 CAS 挡；库存余额加行锁并按固定顺序
取锁防死锁；一次入库的七类写入在单事务里同生共死，第二行超收第一行也跟着回滚。
第四是**库存账**：流水是 append-only（数据库触发器强制），余额是快照，
SUM(流水) == 余额恒等可对账，成本用移动加权平均，冲销按原始金额回滚。

质量上有 229 项后端测试、覆盖率 91%，前端 47 项测试，还有一个五角色可玩的
Dashboard。仓库里 docs/ 有架构、并发、事务这些专题文档。需要的话我可以现场
跑一遍完整业务流程给你看。」
